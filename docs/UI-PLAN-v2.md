## 1. 诊断（按影响排序）

1. **P0 密钥找不到**：15 个 secret 里 14 个藏在「显示高级 → 36 个原始区段」后面；用户配一遍要开高级、点 9 张卡。
2. **P0 两套分类打架**：常用按「服务」（模型/聊天/记忆…），高级按 config 区段（llm/judge/tools…）；同一服务被拆到两个心智模型。
3. **P1 保存不可逆**：dirty 全局累积，只能整体保存/整体放弃；没有单字段撤销、没有刷新守卫 → 填一半刷新全丢。
4. **P1 状态页说谎**：连接卡期待 `online/connected_at`（后端给 `ready/online_sec`）→ 「在线」永不显示；「今日看片」无数据源。
5. **P1 启动页无确认**：一键启动会装依赖/起进程，却是 0 个二次确认；设置页/状态页危险动作都有确认（不一致）。
6. **P2 搜索弱**：只搜当前视图；高级结果要点「显示」才有；搜 `api key` 命中少。
7. **P2 移动端**：只有 760px 容器断点，导航仍占整列；API 页在窄屏是长单列但缺少分组折叠。
8. **P2 可访问性**：tab 键盘已做；secret 的「已设置」没有 `aria-live`；错误不聚焦。

## 2. 信息架构（IA）

保留 5 个 tab，顺序：**启动 → 状态 → API 密钥 → 设置 → 人设**。

| 页面 | 职责 | 不该放什么 |
| --- | --- | --- |
| 启动 | 首次使用：装环境、连 NapCat、启动、看日志 | 任何需要长期调参的字段 |
| 状态 | 运行/连接/情绪/日志/测试消息/重启 | 设置项 |
| **API 密钥** | 所有 key、endpoint、model 三件套；「配一遍就能跑」 | 行为参数（延迟/概率/记忆预算） |
| 设置 | 行为参数：常用（服务分组）+ 高级（原始区段）双视图 | 密钥（只留 `llm.api_key` 一个兼容入口，附「去 API 页」链接） |
| 人设 | 编辑 persona、发测试消息、看上下文/记忆 | 配置 |

规则：
- 任何 secret / endpoint / model 只允许出现在 **API 页**（`llm.api_key` 在设置页保留一行 + 跳转链接，避免老用户找不到）。
- 行为参数只出现在 **设置页**；设置页搜索默认同时搜常用 + 高级，高级命中直接显示（不再要求先开「显示高级」）。
- 启动/状态只放动作，不放表单。

## 4. 设置页重构（Phase 2）

顶部工具条：

```
[搜索：中文标签 / key / 说明（含高级）] [服务视图|原始区段] [仅看已改（x）] [保存改动（x）] [放弃]
```

- **服务视图**（默认）：7 张卡（模型与密钥 / 聊天与回复 / 主动与情绪 / 记忆与人物 / 图片与媒体 / B 站与搜索 / QQ 与服务），每张卡内按「常用在前、高级折叠」排；卡头显示「x 项常用 · y 项高级」。
- **原始区段视图**：现有 36 个 section 卡，仅在切换到该视图时渲染（性能）。
- **搜索**：始终搜常用 + 高级；结果页按「服务分组」展示，高级命中加 `高级` 徽章；顶部显示「共 x 个结果（y 个高级）」。
- **单字段撤销**：每行 dirty 时行尾出现「撤销」按钮（清该 key 的 dirty），不再只有整体放弃。
- **仅看已改**：过滤出 dirty 字段，长表单改动一目了然。
- **高级入口**：设置页顶部保留「显示高级项目」开关 = 切到原始区段视图（保持肌肉记忆）。

验收：
1. 打开设置页默认服务视图，看到 7 张卡；
2. 搜「pixiv」直接出高级结果，不用先开开关；
3. 改 3 个字段 → 卡头/顶部计数 3 → 点单行撤销变 2 → 保存确认列出 2 个中文标签；
4. 切到原始区段视图，36 个区段都在，字段数不变。
