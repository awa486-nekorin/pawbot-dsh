### 2.2 链路（最终形态）

```
QQ → NapCat → PawBot(Python)
  … agent.py 拼 system（人设 v3 + 记忆 + 提示）+ 用户消息 + 工具 schema
  → llm.provider=dsh → brain.turn()
  → POST http://127.0.0.1:<DSH>/pawbot-dsh-brain/turn   （loopback + 一次性 Bearer token）
  → DSH Host：ctx.agents.create()
       ├─ complete 人设段 = 上面那整段 system（模型只看到大肥鱼）
       ├─ preset pawbot-brain：pwsh / read / write / edit / glob / grep / web_search / web_fetch
       ├─ PawBot 30 个工具 → 作用域代理工具 → 回调 POST /api/brain/tool（真 ctx 执行）
       └─ restrict 掉所有继承来的全局工具 + guard 兜底
  → followup → whenIdle → 汇总最终文本 + 媒体段
  ← { text, media, provider, model, tools_used, native_calls, elapsed_ms, … }
  → PawBot 表达层（style.polish / ‖ 分条 / 表情包 / @ 引用 / TTS）→ QQ
```

### 2.3 为什么这么设计（取舍）

- **每轮一个新 Agent**：PawBot 已把聊天历史渲染进 system 块，信息量与旧请求等价；没有跨轮串味。
  代价是每轮在 `~/.dsh/sessions/` 落一份 7~50KB 日志（DSH 持久化语义，没有 delete API）。
- **complete 人设**：模型只看到 PawBot 的 system，不掺 DSH 编码 agent 身份；`brainCompletePersona=false` 可 A/B。
- **程序化 preset**：本部署 web-app 把宿主工具行全 disabled，不挂 preset 的新 Agent 几乎没工具；
  程序化注册不写 `~/.dsh`、插件卸载即消失。
- **restrict + guard 双闸**：restrict 让 `pawbot_restart`/`subagent`/`ask_user_question` 之类**看不见**，
  guard 保证即使模型硬调也**执行不了**。
- **默认 `workspace-write` + `approval=never`**：能读、能跑命令、只能写工作目录/临时目录；
  不弹窗、不挂住；要全盘读写必须显式 `danger-full-access`（一个更危险的档位，文档再三提醒）。
- **失败回退**：env 缺失→配了 `api_key` 才回退 API（否则直接失败，**不会把 mock 文案发进群**）；
  有 env 但这一轮失败且配了 api_key→回退并记警告。

### 2.3b 安全审查后的加固（两个 reviewer，2026-10-27 下午）

审查发现并已修（细节见 `docs/BRAIN.md` §3 与 `docs/BRAIN-VERIFICATION.md` §5）：

| 问题 | 修法 |
|---|---|
| 默认白名单太宽：群友一句话就可能让她读整机文件/跑命令并回群 | **电脑工具默认只给主人**（`account.owner_ids`）；群友轮次不挂 preset、只有 PawBot 业务工具 |
| `conv` 单槽登记：一轮超时后旧轮次残留的工具回调会拿到新 ctx（confused deputy） | `conv` 改成**每轮唯一**（`session_id#uuid`），旧 key 找不到新 ctx → 409 |
| 中断/超时的残句被当成功回复发进群 | `stop_reason != completed` 或超时 → `INTERRUPTED`/`TIMEOUT`，不发残句；超时后再 cancel 一次 |
| guard/restrict 装不上时 fail-open | 执行闸 fail-closed（装不上本轮失败）；allowlist 改成「配置 ∩ 实际挂载」而不是常量全集 |
| 沙箱模块缺失时电脑工具跑在未知沙箱 | 拿不到 sandbox/approval 模块就不挂 preset，本轮 `BRAIN_UNAVAILABLE` |
| 写类 PawBot 工具没有发起人校验 | `remember/edit_persona/account_action/post_qzone/qzone_*/learn_meme/save_sticker/album_add/remind/bili_action` 在回调里再验主人 |
| token 会被 TTS/MCP 等孙进程继承 | PawBot 在 import 时把 brain URL/token 从 `os.environ` pop 掉；日志脱敏加 `pdbrain_` |
| 子进程退出/停止后旧 token 仍有效 | `stopChild` / `error` / `exit` 三处都 `brain.revoke()` |
| body 读取可长时间占用并发槽 / 无上限 | 读 body 单独 10s 限时；PawBot WebUI 总请求体 4MB 上限 + content-length 数字校验 |
| 诊断路由可被浏览器同源读 | `/pawbot-dsh-brain/status` 也拒绝带 `Origin`/`Sec-Fetch-Site` 的请求 |
| 自检因 owner 闸失去电脑工具、证据链失真 | `pawbot_brain selftest/turn` 显式以主人身份跑（不经过 QQ、群友触发不到） |
